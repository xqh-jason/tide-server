## OVERVIEW

`src/entity/` — 21 张表的 SeaORM 实体（20 张建于 baseline 迁移，`sys_refresh_token` 建于 `m20260913_000002`），全局共享（关联表跨域使用）。

**建档理由**：得分 15（23 文件 / 64 个顶层 pub 项（`grep -roh '^pub ' src/entity/*.rs | wc -l`）/ 被所有域引用；独立领域：数据模型与三种生成来源混居）。

## CONVENTIONS

- 三种来源，看文件头第一行区分：`@generated by sea-orm-codegen 1.1.19`（11 个，含 `mod.rs`）、`generated by codegen`（10 个，本仓 `codegen/` crate 产出）、手写（`sys_site_config.rs`）。
- `impl ActiveModelBehavior for ActiveModel {}` 全部为空：审计盖章（`created_by` / `updated_by`）在 repo 层做，不在实体钩子里做。
- 无物理外键（`migrations/src` 里 0 处 `foreign_key`）：只有逻辑外键 + `uk_*` / `idx_*` 索引名约定；跨表查询在 repo 里直接用相关 Entity。
- 时间统一 `NaiveDateTime`（写入 `chrono::Local::now().naive_local()`），`created_at` / `updated_at` 交给 MySQL 默认值 `CURRENT_TIMESTAMP` / `ON UPDATE CURRENT_TIMESTAMP`，实体与 repo 都不显式设值——与迁移定义保持单一事实来源。
- 布尔语义列以 `i8` 0/1 存（`status`、`is_primary`、`is_leader`、`keep_alive`、`hidden`），只在个别 Resp（如 `VbenMenuMeta`）映射成真 `bool`。
- 人字段 `created_by` / `updated_by` / `revoked_by` 为 `u64` 非 `Option`，`0` = 种子 / 系统写入；其 `UserRefIds` impl 不在这里，在 `src/utils/user_ref.rs`（协议见 `utils/AGENTS.md`）。
- 列注释写在字段 doc 注释上（`/// 工号；员工编号，空字符串表示未设置。`），与迁移 DDL 的 `COMMENT` 对应。

## ANTI-PATTERNS

- 不手改 codegen 来源的实体：改 `codegen/defs/<域>.json` 后重新生成（`sys_user` / `sys_menu` / `sys_dept` / `sys_role` / `sys_api` 等 sea-orm-codegen 来源的以迁移 DDL 为准，手工同步）。
- 不把 `Model` 直接返回给客户端：每个响应类型都有 `From<*::Model> for *Resp` 做「字段搬运」，人名字段先置空串再由 `fill_user_names` 填。
- 不在实体里加业务方法、校验或状态判断——那是 service / validate 的职责。
- 不加物理外键约束（与全库约定冲突，且迁移基线明确「表间无外键约束」）。
- 不删除 `prelude.rs`：下次 codegen 会重新生成它。
