# W3 角色域 CRUD 计划：四件套 + 菜单/API 关联事务

> 目标：在 `src/modules/role/{dto,repo,service,api}.rs` 补齐角色域四件套，
> 提供 list/create/update/get/delete 五个端点；update 时在同一事务内重建
> `sys_role_menu` / `sys_role_api` 关联（先删旧、后插新）。
>
> 协作约定（沿用 W3）：AI 编写测试和最终 review；用户手动实现业务代码。

## 接口契约（POST + JSON body，统一 `ApiResult`）

| 端点 | body | 返回 |
|---|---|---|
| `POST /api/v1/role/list` | `{ page?, page_size?, keyword?, status? }` | `PageResult<RoleResp>` |
| `POST /api/v1/role/create` | `{ role_name, role_key, sort?, status?, remark?, menu_ids?, api_ids? }` | `RoleResp` |
| `POST /api/v1/role/update` | `{ id, role_name?, role_key?, sort?, status?, remark?, menu_ids?, api_ids? }` | `RoleResp` |
| `POST /api/v1/role/get` | `{ id }` | `RoleResp` |
| `POST /api/v1/role/delete` | `{ id }` | 成功即 `200` |

说明：
- `menu_ids` / `api_ids` 用 `Option<Vec<u64>>`：`Some(v)` 表示全量替换关联，`None` 表示不修改关联。
- 软删除语义：`sys_role` 主表 `deleted_at IS NULL` 有效；`sys_role_menu` / `sys_role_api`
  关系表硬删除，删除角色时在同一事务内物理清空关联。
- `role_key` 全局唯一（数据库唯一索引 + service 层前置校验），update 时排除自身。
